# AI 比赛工程师（实时问答）设计文档

- 日期：2026-10-18
- 目标版本：v1.4.3（第一期）
- 状态：待批准

## 一、意图与动机

现在的小小领航员是「机械回答」：语音 → 短语库精确匹配 → 意图 → 硬编码规则 → 拼接录音。它有三个天花板：

1. **只认预设问法。** 「我该不该进站」有意图，但问「刚才那个弯为什么慢了 0.3 秒」会被 `router.route()` 的硬拒绝挡掉。
2. **回答是录音素材。** 无法组合出新句子。
3. **不会推理。** 只做「读字段 → 比阈值 → 播录音」，不能跨数据思考。

用户希望它向「真正的比赛工程师」靠近：**在比赛中随时提问，基于当下与近期赛况得到分析性回答。**

明确的范围边界：**只做比赛中实时问答。** 不做赛后回看分析、不做多轮对话、不在本期接 TTS。

## 二、目标与非目标

### 目标

- 比赛中随时提问，能回答**需要跨数据推理**的问题（为什么慢、该不该进站、现在什么策略）。
- 规则层继续作为默认主力：**毫秒级、零成本、离线可用、绝不猜**。
- 大模型只补规则层的短板，且**可关、可选档位**。
- 失败时明确降级：宁可说「现在来不及算」，也不胡说。

### 非目标（本期不做）

- TTS 语音合成（第一期只出文字）。
- 赛后分析、.ibt 文件导入、跨场次数据。
- 多轮追问、主动播报（「你的左前胎在掉」）。
- 替换或削弱现有规则层。

### 反目标（即便技术上跑通也算失败）

- 断网或没配 Key 时软件变得不可用。
- 规则层被绕过，导致比赛中延迟普遍上升。
- 模型编造遥测里没有的数字，并被用户当真。
- API Key 泄漏到日志、界面或仓库。

## 三、约束

- **延迟**：从松键到出字 ≤ **2.5 秒**，其中模型调用 ≤ 2 秒。超时直接降级，不阻塞。
- **网络**：DeepSeek API 需实测连通性；不可用时功能自动禁用，不影响原有功能。
- **成本**：每次问答的输入 token 需可控（见「上下文组装」）。
- **平台**：Windows（PyInstaller 打包），Python 3.12。
- **红线**：现有「绝不猜」原则在规则层不变；模型层的幻觉必须被程序侧校验拦住。

## 四、用户已定的决策

| 决策项 | 选定 |
|---|---|
| 大模型供应商 | **DeepSeek**（OpenAI 兼容格式） |
| 第一期范围 | **只出文字**，不接 TTS |
| TTS 音色 | 本期不涉及 |
| 档位设计 | **做成用户可选项，三档**（用户要求三种都提供） |
| 默认档位 | **C（白名单）** |
| A 档是否保留安全类硬拒绝 | **保留** |

## 五、三档模式（核心产品设计）

三档表达的是「模型接管范围」，而非「是否守底线」。**安全类硬拒绝在所有档位都生效。**

### 安全类硬拒绝（不可越过）

这些与现有 `router.route()` 的立场一致，任何档位都不放行：

- 操作车辆：「替我开」「帮我关」「调高/调低/调到/改成/设置为」
- 解释处罚原因：「处罚是什么」「为什么被罚」「怎么判」「会被罚」
- 遥测范围之外：时间/日期、备胎库存等

### 三个档位

| 档位 | 规则层 | 模型介入时机 | 典型延迟 | 成本 |
|---|---|---|---|---|
| **A 智能全接管** | 先跑，命中即用 | 规则答不上就接管（安全类硬拒绝除外） | 每问 +1~2s | 最高 |
| **B 仅分析模式** | 全权 | 用户显式开启分析模式时才调 | 平时 0 | 按需 |
| **C 白名单（默认）** | 全权 | 仅白名单意图且规则无解时 | 少数问题 | 低 |

### 各档行为细节

**C 档白名单**（默认）：以下意图在规则层给出「答不了」时，转交模型：

- `query_laptime`（圈速分析）
- `query_pit`（进站决策）
- `query_fuel`（燃油策略）
- `query_gap` / `query_opponent`（对手态势）
- `query_weather`（天气策略）
- `query_damage`（车损影响）

**A 档**：任何非安全类拒绝都尝试模型。附加**限流**：每分钟最多 6 次模型调用，超出直接降级并提示。

**B 档**：默认完全走规则。用户通过界面开关或独立 PTT 键进入「分析模式」，该模式下等同 A 档（含限流）。离开分析模式自动恢复。

## 六、数据层：从「瞬时快照」到「分层缓冲」

### 现状

`TelemetrySampler` 已以 60Hz 持续采样（`telemetry.py:488`），`DerivedTracker` 维护油量中位数、差距 6 秒窗口。**池子只有当下，没有历史。**

### 新增：`LapHistoryTracker`

在每圈边界（`lap` 递增）写一条聚合记录，环形缓冲保留最近 **20 圈**：

```python
{
  "lap": 13,                       # 圈号
  "lap_time": 83.512,              # 该圈用时（秒）
  "fuel_start": 18.4,              # 圈初油量
  "fuel_used": 1.42,               # 该圈油耗
  "tyre": {"LF": {"temp": 92.1, "wear": 0.87}, ...},   # 圈末胎况
  "position": 4,                   # 圈末名次
  "class_position": 3,
  "gap_ahead_s": 1.8,
  "gap_behind_s": 1.2,
  "flags": ["green"],              # 该圈出现过的旗号集合
  "in_pit": false,                 # 该圈是否进过站
  "air_temp": 28.0,
  "track_temp": 41.0,
  "wetness": 1,
  "incidents": 2,
}
```

**只记录有效圈**：进站圈、非连续圈、重置后的首圈不写。

### 派生摘要（给模型用）

组装时额外计算：

- 最近 3/5/10 圈平均圈速、标准差
- 圈速趋势（在变快还是变慢）
- 油耗趋势
- 胎温趋势（每轮）
- 名次变化
- 前后车差距变化

### 为什么分层而不是全存

模型的上下文有限且收费。问「还有多少油」只需瞬时 3 个字段；问「为什么慢」才需最近 5 圈完整记录。**按问题取层，比每次塞全量便宜一个数量级。**

## 七、上下文组装（`race_context.py`）

按问题类型组装紧凑 JSON，控制在 **1500 token 以内**：

```python
{
  "now": { ... 瞬时关键字段 ... },
  "recent_laps": [ ... 最近 N 圈 ... ],
  "derived": { ... 趋势摘要 ... },
  "session": { ... 比赛信息：总圈数、剩余、旗号 ... }
}
```

- 简单问题（还有多少油）：只给 `now` + `derived`
- 分析型问题（为什么慢）：给 `now` + `recent_laps`（最近 5 圈）+ `derived`

## 八、模型调用层（`llm_engine.py`）

### 接口

- OpenAI 兼容 `POST /chat/completions`
- 配置项：`base_url`、`api_key`、`model`、`timeout_s`、`max_tokens`
- 默认：`base_url = https://api.deepseek.com`，`model = deepseek-chat`

### 系统提示词要点

- 你是 iRacing 比赛工程师，只能基于提供的遥测数据回答
- 数据里没有的，明确说「现在读不到」，**不要推测**
- 回答简短口语化，**不超过 60 字**
- 不解释推理过程，直接给结论
- 不提供调校或操作指令
- 不解释处罚原因

### 输出契约（强制 JSON）

```json
{
  "answer": "你的油还够跑 6.2 圈，比赛还剩 5 圈，不用进站。",
  "confidence": 0.9,
  "refused": false,
  "data_used": ["laps_of_fuel", "laps_remain"]
}
```

## 九、三道校验闸（防幻觉核心）

模型返回后，程序侧依次校验，**任何一道不通过即降级为「答不了」**：

### 1. 长度闸

`answer` 超过 60 个中文字符 → 截断或拒绝。开车没时间听长段。

### 2. 数据闸

`data_used` 中的每个字段名必须真实存在于本次组装给模型的上下文里。出现不存在的字段 → 拒绝。

### 3. 数字闸

从 `answer` 中提取所有数字（含小数），每个数字必须能在上下文中找到匹配值（容差：整数 ±0.05，一位小数 ±0.06，百分比 ±0.5）。

允许的例外：序数词（第几名）、明确来自问题本身的数字、时间单位换算（如「还剩 2 分 30 秒」由 150 秒换算）。

**对不上 → 拒绝播报，退回「现在读不到可靠数据」。**

## 十、失败与降级

| 情况 | 行为 |
|---|---|
| 未配置 API Key | 功能禁用，界面显示「AI 分析未配置」，规则层照常 |
| 网络不可达 | 超时 2 秒后放弃，返回「现在连不上分析服务」 |
| 模型返回非法 JSON | 重试 1 次，仍失败则降级 |
| 三道校验任一失败 | 降级为规则层的「答不了」话术 |
| 超过限流 | 直接降级并提示「问得太频繁」 |

**原则：任何失败都不阻塞、不崩溃、不改变规则层的正常行为。**

## 十一、配置项

写入 `voice_assistant/config.yaml`（无密钥部分）与 `config.local.yaml`（密钥）：

```yaml
ai:
  enabled: false                    # 总开关，默认关
  mode: "whitelist"                 # whitelist | analysis | full
  provider: "deepseek"
  base_url: "https://api.deepseek.com"
  model: "deepseek-chat"
  timeout_s: 2.0
  max_tokens: 300
  max_answer_chars: 60
  rate_limit_per_min: 6
  whitelist_intents:                # C 档白名单
    - query_laptime
    - query_pit
    - query_fuel
    - query_gap
    - query_opponent
    - query_weather
    - query_damage
  # api_key 只放 config.local.yaml 或环境变量 LITTLE_NAVIGATOR_AI_KEY
```

**密钥处理**：不写入 `config.yaml`（随包分发）、不写日志、界面输入框做掩码。
