# 1.4.5 界面设计记录

使用 ui-ux-pro-max 与 design-taste-frontend。方向抽取 seed 1781840238，选择 Data terminal：长时间驾驶环境下的中性深色、等宽数字与克制的状态色。未采用 ui-ux 搜索里不适合原生工具的营销页、玻璃模糊建议；采用其键盘焦点、表单标签、对比度、反馈与减少动态的规则。

## 产品与任务

- 驾驶员的注意力在赛道，主界面回答“领航员能否回应、刚才说了什么”。
- 真实来源为 iRacing SDK；未连接时所有遥测清空，不保留旧值冒充实时值。
- PTT、AI、播报、改车有独立状态；错误给出可到达的恢复入口。
- 最近问答是产品输出，作为主块；数字并列读，单位与零值不隐藏。
- 油量 L、名次、圈数、上一圈时间各有固定格式；不添加假趋势、假赛道图或示例排名。
- 进站服务是产品特有元素：四个轮胎读回图、加油目标 L、快修状态，全部只读。
- 语音输入包括麦克风、识别模型、键盘/鼠标/方向盘按键绑定。
- 音量与耳机路由在各自设置页，保留现有服务能力。
- AI 配置与能实际操作游戏的进站控制分为两页，避免混淆。
- 文字试问先预览；执行并播报是独立、清楚标注的操作。

## 视觉与布局

采用 Public Sans 本地字体，中文回退 Microsoft YaHei UI；JetBrains Mono 仅用于数字、计时与代码。保留角色头像与原合作品牌署名。

抽取的 50px 图标栏不适合十个中文目的地，因此重抽 shell 为 Open plane，改用带文字的导航。原生标题栏只负责产品名、会话与窗口操作。选择用 1px 蓝色底线表示，不用彩色选中块。

初始原生窗口为 1180×820，可调整且最小 900×650。1180px 下，208px 导航 + 2×24px 主区留白 + 924px 内容 = 1180px；主区双栏按 1.7fr/1fr 分配，间隔 24px。窄屏导航折叠为抽屉，内容顺序保持最近回答、核心遥测、进站服务。

页面问题：控制台=能否回应；问答记录=刚才发生了什么；诊断=哪里需要排查；语音输入=怎么说话；语音播报=听到什么；音频路由=从哪里听；AI工程师=如何接入模型；进站控制=允许什么操作；识别设置=哪些问法能识别；文字试问=这句话会产生什么结果。

仅状态变化有短过渡，无入场表演；支持减少动态。所有生产数据由 API 驱动，测试夹具仅用于 QA。

## 最终检查与修改

最初三个最差问题是：旧窗口信息混杂、进站图标签挤在一起、AI 表单过长且跨页丢草稿。新版使用十个明确目的地和双工作区控制台；轮胎标签改为紧凑的左右布局；AI 主配置两列、次配置折叠，草稿留在当前窗口内存。

真实 Edge 交互测试 16 组通过，包含全部页面及 375–1440px 布局。设计检查第三轮在 1440/768/390px 无 FAIL、无未豁免 WARN。设置页、窄屏和控制台截图均人工查看。

静态 lint 0 FAIL；保留四项 WARN 的理由：三处等宽字体声明仅服务数字、计时和代码，符合 Data terminal 方向；39 个破折号是未读到数据的占位，不是文案标点。浏览器检查只豁免 no-data-hue：控制台唯一 SVG 是只读汽车轮廓，未知勾选必须保持中性，不能为满足图表色彩规则给未知数据着色。真实统计图使用 API 数据并有状态色。

没有装饰图表、假涨跌或假比赛数据；截图夹具明确标明模拟模式。保留原头像和合作署名。新增字体在本机加载并附 OFL 许可。设计抽取信息保留于 `.taste-skill/direction.json`。
