# README 排版方向

使用 GitHub 连接器核实发布和现有 README；花叔 Design 用于先出可见草稿，imagegen 已试作一张概念图，但用户明确不要复杂图片后弃用，不加入交付资产。design-taste-frontend 与 UI/UX Pro Max 仅借用信息层级和可读性建议；网页动效、CSS、场景和装饰不适用于本次 GitHub README。

三版共用原始 logo、相同产品事实、普通 GitHub 白底文档风格。正文 16px、行高 1.8，文档最大宽度 854px 内容区；手机单列。只有正常链接蓝，没有背景渐变或宣传式图片。最终中文字体跟随 GitHub，不嵌入特殊字体。

## A：阅读优先（推荐）

- 白底、深灰正文、标准蓝链接。标题 32px，正文 16px，左对齐，段落间留白。
- 顶部由项目名、一句话定位、版本/系统/许可、四个导航链接组成；不制作插画 banner。
- IFP、MoonDrop、车队三标同行，保留各自身份文字；随后说明用户价值、三步安装、问法例子。
- 软件截图放在读者已理解项目之后。无虚构数据或独立装饰功能图。
- 内容来源决定形式：驾驶员需要快速判断“是什么、怎么用”，所以用正常阅读顺序承载真实说明。

## B：品牌居中

- 同样使用白底与标准字体。车队 logo 与项目名居中，正文左对齐。
- 车队作为视觉识别，赞助商两个标识安静分列，不加入 slogan 大字或复杂图片。
- 项目介绍之后先放真实软件截图，再列安装与功能；适合更强调项目身份和产品外观。
- 内容来源决定形式：已有车队与赞助资产值得被看见，但不抢正文。

## C：快速开始

- 白底、左对齐，轻量项目署名后直接说明使用价值。
- 首先给三个清楚入口：直接安装、只装 Spotter、接 AI/参与开发。
- 接下来是安装步骤和例子。三个 logo 放在有标题的感谢区，不混淆赞助与项目功能。
- 内容来源决定形式：项目同时服务普通玩家、语音包用户与开发者，入口需要先分清。

## 备选与过程

最初曾考虑赛车摄影、技术展示和社区角色三类视觉方向。已核实 Godot、Immich 的 README，借用前者清晰说明与后者真实截图做证据的思路。风格样张也查看过，但用户的新偏好优先：不再制作六格复杂画板，不把 README 做成独立营销网站，不采用生成图片。三份完整 HTML 是本地排版提案，不代表最终 README 依赖 CSS。
