# 2026-10-19 真机测试修复（基于 v1.4.4）

这是未发布的本地修复分支 `codex/fix-live-race-control`，基线提交 `3036756`。没有覆盖 `D:\LittleNavigator`，也没有上传 GitHub Release。

## 本场证据

真实 iRacing 遥测正常变化，但改车控制器一直 `available:false`。第 3 分钟取消换胎，以及第 4 分钟左侧换胎、加 10 L、取消快修、勾选快修的五次请求，都在改车发送前被“未连接游戏”拒绝；游戏仍保持原四胎与 100 L 目标。

测试投递器后续的虚拟音频输入未完成全链路验证，不能把它当成 ASR、AI 或 TTS 已通过。本轮修复采用可复现的模拟 SDK/模型回归，以及真实打包窗口检查；没有用 SDK 绕过软件改游戏来伪造成功。

## 修改

- **独立 SDK 连接**：改车控制器在可用性检查/操作前初始化自己的连接，掉线后节流重连；状态轮询不发送广播，失败操作不自动重放；热重载和退出释放自己持有的连接。
- **准确选择轮胎**：单角/部分角位先取消四胎勾选，再选择目标角位，保留其他服务。回读比较完整轮胎掩码，默认四胎仍亮时不能宣称“只换左侧”成功。
- **准确确认取消**：清空、取消轮胎/加油/挡风/快修都回读对应位已熄灭；读不到不是成功。取消加油/快修/挡风不再落到失败播报；六条取消确认素材改为中性“已取消”，避免单项取消播成“全部清空”。
- **加油目标回读**：除了 Fuel 勾选位，还读取 `PitSvFuel`，确认实际目标升数。已有加油勾选但目标仍 100 L 时不能把 10 L 请求判成功。
- **小数明确拒绝**：当前进站广播使用整数参数；1.5/0.5 L 不再静默取整/钳为整数发送，而明确报告未执行。文本解析仍可识别数值，但不伪装成游戏支持小数。`加满`计算若得到小数，本修复也会明确拒绝，待支持真实油箱粒度后再扩展。
- **文字问答与 AI**：`/api/ask` 的真实播报路径在规则需要转交时调用同一 AI 流程，返回最终答案；纯预览不执行、不调模型。修复转交失败时把 RingLog 当函数调用的二次异常。
- **播报一致性**：学习库命中也走已配置 TTS；关闭播放器不再标记成 TTS 已播放；已播完动态答案后不再追加“请看屏幕”。
- **剩余时间问法**：补入“还剩多久/还剩多少时间/剩余时间多少/还有多少时间”的精确短语，避免与“必修还剩多久”的拼音模糊匹配相互拒绝。
- **调试台**：操作预览显示改车类别，按钮明确标为“执行并播报（更改进站设置）”；无规则片段时也能执行真实问答转交 AI，并展示最终 AI 文本。

## 第二轮修复：1.4.4-livefix2

真实比赛发现咨询快修被当作操作、圈差答成秒差、多近答成趋势、维修时间与自然分析问法未识别。本轮修复：

- 命令边界按无标点语义判断“是否/有没有/需不需要/解释/分析”等，快修、撕膜还必须匹配明确请求句式；状态描述不能仅凭服务名称触发操作。保留“快修”“撕膜”快捷口令，因此语音仅识别出“快修”时仍按该口令执行，不能从没有保留的语调推断疑问。
- 圈差问题明确说明缺少可靠圈差，不用秒差替代，也不让 AI 再从秒差推测；“后车离我多近”回答数值距离。
- “维修还剩多久”在严格语音模式可识别，维修未开始会说明计时无效；已开始时读取维修时间。
- “稳定性怎么样/总结/有什么变化”等进入分析路径；分析问题不再被单一油量事实回答提前截断。
- AI 在模型返回后和 TTS 合成完成、实际播放前核对连接、场次、进站状态、快修次数及加油变化；超过现有 3.5 秒实时生成预算或状态变化则丢弃旧答案/模板，播报固定“数据已经变化，请重新提问”。这限制的是出声前的数据年龄，不截断正在播放的完整回答，也不保证外部服务始终能按时返回。
- 数值校验失败保留模型原回答和实际校验上下文，便于区分幻觉与误杀；不放宽数值校验来掩盖拒答。
