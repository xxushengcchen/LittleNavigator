# AI 比赛工程师（实时问答）设计文档

- 日期：2026-10-18
- 目标版本：v1.4.3（第一期）
- 状态：待批准

## 一、意图与动机

现在的小小领航员是「机械回答」：语音 → 短语库精确匹配 → 意图 → 硬编码规则 → 拼接录音。它有三个天花板：

1. **只认预设问法。** 「我该不该进站」有意图，但问「刚才那个弯为什么慢了 0.3 秒」会被 `router.route()` 的硬拒绝挡掉。
2. **回答是录音素材。** 无法组合出新句子。
3. **不会推理。** 只做「读字段 → 比阈值 → 播录音」，不能跨数据思考。

用户希望它向「真正的比赛工程师」靠近：**在比赛中随时提问，基于当下与近期赛况得到分析性回答。**

明确的范围边界：**只做比赛中实时问答。** 不做赛后回看分析、不做多轮对话、不在本期接 TTS。

## 二、目标与非目标

### 目标

- 比赛中随时提问，能回答**需要跨数据推理**的问题（为什么慢、该不该进站、现在什么策略）。
- 规则层继续作为默认主力：**毫秒级、零成本、离线可用、绝不猜**。
- **模型由用户自己接**：软件提供 OpenAI 兼容的 API 接入口，不绑定任何厂商。
- **软件自身的响应速度有硬保障**，不因用户接了慢模型而退化。
- 失败时明确降级：宁可说「现在来不及算」，也不胡说。

### 非目标（本期不做）

- TTS 语音合成（第一期只出文字）。
- 赛后分析、.ibt 文件导入、跨场次数据。
- 多轮追问、主动播报。
- 替换或削弱现有规则层。
- 内置任何厂商的 API Key 或代为付费。

### 反目标（即便技术上跑通也算失败）

- 断网或没配 Key 时软件变得不可用。
- 规则层被绕过，导致比赛中延迟普遍上升。
- 模型编造遥测里没有的数字，并被用户当真。
- 用户接入慢模型后，整个软件变得卡顿或不可用。
- API Key 泄漏到日志、界面或仓库。

## 三、约束

- **延迟**：见「六、响应速度保障」的硬约束。
- **网络**：由用户自己的模型服务决定；不可用时功能自动禁用，不影响原有功能。
- **成本**：由用户自行承担；软件只负责控制上下文规模。
- **平台**：Windows（PyInstaller 打包），Python 3.12。
- **红线**：现有「绝不猜」原则在规则层不变；模型层的幻觉必须被程序侧校验拦住。

## 五、三档模式（核心产品设计）

三档表达的是「模型接管范围」，而非「是否守底线」。**安全类硬拒绝在所有档位都生效。**

### 安全类硬拒绝（不可越过）

与现有 `router.route()` 的立场一致，任何档位都不放行：

- 操作车辆：「替我开」「帮我关」「调高/调低/调到/改成/设置为」
- 解释处罚原因：「处罚是什么」「为什么被罚」「怎么判」「会被罚」
- 遥测范围之外：时间/日期、备胎库存等

### 三个档位

| 档位 | 规则层 | 模型介入时机 | 典型延迟 | 成本 |
|---|---|---|---|---|
| **A 智能全接管** | 先跑，命中即用 | 规则答不上就接管（安全类硬拒绝除外） | 每问 +1~2s | 最高 |
| **B 分析按键** | 全权 | **按住专用分析键提问时**，走模型路径 | 按需 | 按需 |
| **C 白名单（默认）** | 全权 | 仅白名单意图且规则无解时 | 少数问题 | 低 |

### 各档行为细节

**C 档白名单**（默认）：以下意图在规则层给出「答不了」时，转交模型：

- `query_laptime`（圈速分析）
- `query_pit`（进站决策）
- `query_fuel`（燃油策略）
- `query_gap` / `query_opponent`（对手态势）
- `query_weather`（天气策略）
- `query_damage`（车损影响）

**不含** `query_flags`（旗号）：规则层答得准，模型没必要插手。

**A 档**：任何非安全类拒绝都尝试模型。受「六、响应速度保障」的限流与自适应降级约束。

**B 档（分析按键）**：默认完全走规则。用户按住**专用分析键**提问时：
- 问题直接进入模型路径（不再等规则层「答不上」）
- 安全类硬拒绝仍然先拦
- 松键后立即进入模型调用，受同一套硬截止约束

按键绑定复用现有的按键采集 UI，与 PTT 分开配置（`ai.analysis_key`）。**默认不绑定**，避免与游戏内按键冲突。

**首次使用引导（必做）**：用户第一次启用 AI 功能（或选择 B 档）时，界面弹出引导，要求采集一次分析键才能完成配置。引导需说明：

- 这个键只用于「按住提问、走 AI 分析」，与 PTT 是两套按键
- 采集前请先确认该键在 iRacing 里没有绑定其他功能
- 采集失败或跳过时，B 档保持不可用（灰显），并说明原因

不允许出现「B 档已选但键没绑、按了没反应」的状态——要么引导完成绑定，要么 B 档明确不可用。

## 六、响应速度保障（硬约束，代码内强制）

### 6.1 先明确能做到什么

**软件无法让一个慢模型变快。** 本设计保证的不是「任何模型都在 2 秒内答完」，而是：

> **无论用户接入什么模型，软件自身的响应路径永远不会因模型而变慢或卡死。**

具体表现：规则层照常毫秒级出结果；模型超时立刻砍掉并给出明确提示；用户不会经历「按了没反应」或「界面卡住」。

### 6.2 三级时间预算

| 层级 | 预算 | 说明 |
|---|---|---|
| 规则层 | ≤ 50 ms | 命中即播报，模型完全不参与 |
| 模型首字 | ≤ 1.5 s | 超过视为本次不可用 |
| 模型全答 | ≤ 2.0 s | 硬截止，到点主动取消请求 |

### 6.3 代码内强制（配置只能收紧，不能放宽）

以下写在代码常量里；`config.yaml` 只能设得更小，设更大时被钳制并在日志告警：

- `DEADLINE_HARD_MAX = 2.0s`
- `MAX_INPUT_TOKENS_HARD = 1500`
- `MAX_OUTPUT_TOKENS_HARD = 300`
- `SINGLE_INFLIGHT = True`（同一时刻只允许一个模型请求，新请求取消旧请求）

### 6.4 永不阻塞的四条规则

1. **规则先行**：规则层能答的问题，永远不进入模型路径（B 档分析键除外，那是用户显式要求）。
2. **立即反馈**：需要模型时立刻返回「正在分析」，界面不空等。
3. **硬性取消**：到截止时间主动 abort HTTP 请求，不赌「可能马上回来」。
4. **上下文裁剪**：超预算时先砍远圈、再砍对手细节，保证输入 token 不成为延迟主因。

### 6.5 连接与预热

- 复用 HTTP 连接（keep-alive），避免每次重新 TLS 握手
- 启动后与首次提问前各发一次极小预热请求（`max_tokens=1`）
- 记录每次往返延迟，供自适应降级判断

### 6.6 自适应降级

- 记录最近 10 次调用延迟
- **连续 3 次超时**，或 **p90 > 1.8 s** → 自动关闭模型路径，界面提示「当前模型太慢，已暂时关闭 AI 分析」
- 用户可手动重试恢复；恢复后重新统计

### 6.7 明确不承诺

- 不承诺第三方模型的可用性、准确率或输出格式
- 不承诺网络抖动下的延迟
- 不承诺超出预算的复杂分析（宁可说「来不及算」）

## 七、数据层：从「瞬时快照」到「分层缓冲」

### 现状

`TelemetrySampler` 已以 60Hz 持续采样（`telemetry.py:488`），`DerivedTracker` 维护油量中位数、差距 6 秒窗口。**池子只有当下，没有历史。**

### 新增：`LapHistoryTracker`

在每圈边界（`lap` 递增）写一条聚合记录，环形缓冲保留最近 **20 圈**：

```python
{
  "lap": 13,
  "lap_time": 83.512,
  "fuel_start": 18.4,
  "fuel_used": 1.42,
  "tyre": {"LF": {"temp": 92.1, "wear": 0.87}, ...},
  "position": 4,
  "class_position": 3,
  "gap_ahead_s": 1.8,
  "gap_behind_s": 1.2,
  "flags": ["green"],
  "in_pit": false,
  "air_temp": 28.0,
  "track_temp": 41.0,
  "wetness": 1,
  "incidents": 2,
}
```

**只记录有效圈**：进站圈、非连续圈、重置后的首圈不写。

### 派生摘要（给模型用）

- 最近 3/5/10 圈平均圈速、标准差
- 圈速趋势（变快或变慢）
- 油耗趋势
- 胎温趋势（每轮）
- 名次变化
- 前后车差距变化

## 八、上下文组装（`race_context.py`）

按问题类型组装紧凑 JSON，控制在 **1500 token 以内**：

```python
{
  "now": { ... 瞬时关键字段 ... },
  "recent_laps": [ ... 最近 N 圈 ... ],
  "derived": { ... 趋势摘要 ... },
  "session": { ... 总圈数、剩余、旗号 ... }
}
```

- 简单问题：只给 `now` + `derived`
- 分析型问题：`now` + `recent_laps`（最近 5 圈）+ `derived`
- 超预算时按「先砍远圈、再砍对手细节」的顺序裁剪

## 九、模型调用层（`llm_engine.py`）

### 接口：OpenAI 兼容，用户自填

**不绑定任何厂商。** 用户填 `base_url` / `api_key` / `model`，软件按 OpenAI Chat Completions 协议调用。国内主流厂商与本地推理大多兼容这一格式。

### 预设（只是预填默认值，用户可改）

| 预设 | base_url | 示例 model |
|---|---|---|
| DeepSeek | `https://api.deepseek.com` | `deepseek-chat` |
| 火山方舟 | `https://ark.cn-beijing.volces.com/api/v3` | 用户填接入点 ID |
| 月之暗面 | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` |
| 本地 Ollama | `http://127.0.0.1:11434/v1` | `qwen2.5:7b` |
| 自定义 | 用户填 | 用户填 |

### 兼容性处理

- **不支持 JSON mode** → 退回「提示词要求 JSON + 程序侧解析 + 失败重试」
- **不支持流式** → 退回一次性返回（延迟更高，但仍受硬截止约束）
- **返回格式异常** → 降级

### 连接自检（界面「测试连接」按钮）

发一条最小请求，报告：连通性、往返延迟、是否支持流式、是否支持 JSON mode。用户装完就能判断自己接的模型够不够快。

### 系统提示词要点

- 你是 iRacing 比赛工程师，只能基于提供的遥测数据回答
- 数据里没有的，明确说「现在读不到」，不要推测
- 回答简短口语化，不超过 60 字
- 不解释推理过程，直接给结论
- 不提供调校或操作指令，不解释处罚原因

### 输出契约（强制 JSON）

```json
{
  "answer": "你的油还够跑 6.2 圈，比赛还剩 5 圈，不用进站。",
  "confidence": 0.9,
  "refused": false,
  "data_used": ["laps_of_fuel", "laps_remain"]
}
```

## 十、三道校验闸（防幻觉核心）

模型返回后依次校验，**任一道不通过即降级为「答不了」**：

### 1. 长度闸

`answer` 超过 60 个中文字符 → 截断或拒绝。

### 2. 数据闸

`data_used` 中每个字段名必须真实存在于本次给模型的上下文里。出现不存在的字段 → 拒绝。

### 3. 数字闸

从 `answer` 提取所有数字（含小数），每个数字必须能在上下文中找到匹配值（容差：整数 ±0.05，一位小数 ±0.06，百分比 ±0.5）。

允许例外：序数词（第几名）、来自问题本身的数字、由秒换算出的分秒表述。

**对不上 → 拒绝播报，退回「现在读不到可靠数据」。**

## 十一、失败与降级

| 情况 | 行为 |
|---|---|
| 未配置 API | 功能禁用，界面显示「AI 分析未配置」，规则层照常 |
| 网络不可达 | 超时后放弃，返回「现在连不上分析服务」 |
| 模型返回非法 JSON | 重试 1 次，仍失败则降级 |
| 三道校验任一失败 | 降级为规则层的「答不了」话术 |
| 超过限流 | 直接降级并提示「问得太频繁」 |
| 连续超时 / p90 超标 | 自动关闭模型路径并提示，可手动恢复 |

**原则：任何失败都不阻塞、不崩溃、不改变规则层的正常行为。**

## 十二、配置项

`voice-assistant/config.yaml`（无密钥部分）：

```yaml
ai:
  enabled: false                    # 总开关，默认关
  mode: "whitelist"                 # whitelist | analysis_key | full
  provider: "custom"                # deepseek | ark | moonshot | ollama | custom
  base_url: "https://api.deepseek.com"
  model: "deepseek-chat"
  api_key: ""                       # 建议留空，用 config.local.yaml 覆盖
  timeout_s: 2.0                    # 只能调小，代码钳制上限 2.0
  max_tokens: 300                   # 代码钳制上限 300
  max_answer_chars: 60
  rate_limit_per_min: 6
  analysis_key: null                # B 档专用按键，默认不绑；首次启用 AI 时引导采集
  whitelist_intents:
    - query_laptime
    - query_pit
    - query_fuel
    - query_gap
    - query_opponent
    - query_weather
    - query_damage
```

`config.local.yaml`（用户密钥，明文，不进仓库、不进安装包）：

```yaml
ai:
  api_key: "sk-..."
```

也支持环境变量 `LITTLE_NAVIGATOR_AI_KEY`，优先级高于配置文件。
